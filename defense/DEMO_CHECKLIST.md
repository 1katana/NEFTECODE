# Демонстрация Нефтекод 2.0

## Запуск

Терминал 1, из корня проекта:

```powershell
.\run-api.ps1
```

Терминал 2:

```powershell
.\.venv\Scripts\python.exe -m http.server 4173 --directory orchestrator/frontend/dist
```

Открыть:

- операторский экран: `http://127.0.0.1:4173`;
- Swagger: `http://127.0.0.1:8000/docs`;
- офлайн-бенчмарк: `integration/dashboard/benchmark.html`.

## Сценарий показа на 4 минуты

1. **Архитектура.** Вход и шестичасовая история проходят через QualityAgent,
   ReliabilityAgent, Optimizer + Safety и Orchestrator. На экране должно быть
   `4/4 OK`.
2. **Полный расчёт.** Экран автоматически запускает «Расчётная смесь».
   Ожидаемый результат: `KEEP`, прогноз серы около `7,27 мг/кг`, Reliability
   `HIGH`, лучший вариант `NO_CHANGE`.
3. **Граница доказательств.** Показать метку `API · SYNTHETIC · расчётная смесь`.
   Телеметрия и ПАК исторические, а смесь 80/20 и свойства второго компонента
   являются допущением.
4. **Защитный отказ.** В списке API выбрать «Исторический срез · без рецептуры»
   и нажать «Выполнить расчёт». Ожидаемый результат: `REFUSE`; Reliability даёт
   числовую оценку, Quality сообщает `BLENDING_PLAN_MISSING`.
5. **Бенчмарк.** Показать сравнение Quality с ПАК, частоты сигналов Reliability
   и таблицу 11 сквозных запусков: `1 KEEP`, `10 REFUSE`.

## Что говорить про решение

- QualityAgent обучен на календарном разбиении и в runtime использует ПАК как
  точечную оценку, а модели дают риск и интервал.
- ReliabilityAgent обучен и выдаёт индекс отклонения режима для четырёх групп.
  В истории нет меток отказов, поэтому индекс не называется вероятностью аварии.
- `REFUSE` является корректным результатом при неполных данных или отсутствии
  подтверждённой рецептуры.
- `RECOMMEND` на изменение уставок заблокирован до утверждения рабочих границ,
  шага изменения и динамики отклика кандидата.

## Что не заявлять

- что смесь 80/20 является заводской рецептурой;
- что диапазоны `T6/F9/P13` утверждены технологом;
- что Reliability предсказывает поломку или аварию;
- что система готова автоматически менять режим установки;
- что метрики test являются результатом нового независимого holdout.

## Если API недоступен

Операторский экран откроет сохранённые контрактные примеры. Они показывают
верстку `RECOMMEND / KEEP / REFUSE`, но не являются результатом текущих моделей.
Для защиты следует восстановить API и дождаться надписи `API доступен · KEEP`.

## Контроль перед выступлением

- `GET /api/v1/health` отвечает `READY_FOR_SHADOW_WITH_BLOCKERS`;
- расчётная смесь возвращает `KEEP`;
- исторический срез возвращает `REFUSE`;
- экран показывает источник каждого расчёта;
- дашборд содержит `1 KEEP` и `10 REFUSE`;
- использовать презентацию `../neftecode_2_0_hackathon_final.pptx`.
