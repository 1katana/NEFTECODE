# Нефтекод — пересборка данных v2

## Что изменено

Эта версия пересобрана по новой логике без генерации синтетических измерений.

Главное изменение: 10-минутная оперативная витрина больше не считается обучающим датасетом.  
Для ML используется отдельный набор, где одна строка соответствует реальному времени лабораторного события ЛИМС на финальной точке продукта: **Гидроочистка / точка 2 / Дизельное топливо**.

## Источники

- ЛИМС: `ЛИМСы 01.01.2023 - н.в_ (2).xlsx`
- ПАК: `Выгрузка ПАК 01.01.2023 - н.в_.xlsx`
- режимные признаки: 27 ключевых тегов из исходного `view_orchestrator.csv`

Исходные файлы не изменялись и не перезаписывались.

## Файлы

- `lims_measurements_v2.csv` — нормализованный long-формат всех исходных ЛИМС с сохранением установки, точки отбора, продукта, показателя, raw value и флагов.
- `lims_hydro2_measurements_v2.csv` — исходные ЛИМС только для финальной точки Гидроочистка / точка 2.
- `pak_measurements_v2.csv` — нормализованные ПАК Mg.Sulfur и D15.
- `view_quality_v2.csv` — оперативная 10-минутная витрина качества. ЛИМС и ПАК хранятся раздельно, age считается реально; `best` выбирает ЛИМС в пределах freshness, иначе ПАК.
- `process_state_v2.csv` — базовый ProcessState: 27 ключевых режимных тегов + оперативные значения качества и metadata.
- `quality_training_hydro2_v2.csv` — обучающая таблица для моделей качества.
- `split_train_v2.csv`, `split_val_v2.csv`, `split_test_v2.csv` — хронологические split только из строк, где есть свежая телеметрия.
- `manifest_v2.json` — машинно-читаемое описание правил и статистики.

## Как построен training dataset

Для каждого реального LIMS-события используются только данные из прошлого:

- текущий последний доступный режимный state;
- лаги 30 мин, 1 ч, 2 ч, 4 ч, 6 ч;
- rolling mean/std/min/max/coverage за 1/2/4/6 ч;
- trend proxy за 1/2/4/6 ч;
- последнее ПАК-значение серы и D15 + возраст;
- предыдущий ЛИМС каждого показателя + возраст.

Будущие значения не используются.

## Split

- train: до `2026-01-01`
- validation: `2026-01-01` — `2026-04-30`
- test: с `2026-05-01`

Эти границы совпадают с прежней логикой split.

Строк в обучающем наборе: **1888**.  
С валидным свежим process state: **1884**.

Содержание серы:
- реальных LIMS target: **1462**
- `S > 10 мг/кг`: **230**

## Что принципиально НЕ делалось

- не создавались синтетические ЛИМС-строки;
- `NaN` не заменялся на 0;
- редкие/off-spec значения не удалялись автоматически;
- ПАК не использовался как target;
- один LIMS-анализ не размножался на 10-минутные target-строки;
- CONTROL-теги не угадывались по имени;
- VAK не синтезировался при отсутствии отдельного raw-источника.

## Что ещё надо подтвердить вручную

1. Семантику timestamp ЛИМС: время отбора пробы / регистрации / получения результата.
2. Актуальный справочник тегов и их физический смысл.
3. Какие теги относятся к `CONTROL`, а какие к `STATE`, `TARGET`, `LIMIT`.
4. Допустимые диапазоны и максимальные delta для CONTROL.

Пока пункт 1 не подтверждён, временные лаги и rolling features считаются **рабочей, но предварительной** привязкой.
