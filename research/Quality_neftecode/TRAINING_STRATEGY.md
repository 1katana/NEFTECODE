# Стратегия обучения QualityAgent: выбранный вариант

Дата решения: 2026-09-18.

## Решение

Timestamp ЛИМС подтверждён как **время отбора пробы**. Одна проба ЛИМС остаётся
одним объектом обучения. Признаки строятся только из данных, доступных не позже
timestamp пробы; отдельно от обучения runtime не раскрывает результат лаборатории
раньше `sample_timestamp + 4h`.

Основная регрессия обучается на всех лабораторных результатах с `MAE`. Три значения
выше 100 мг/кг не удаляются и не винзоризируются. Одновременно обязательно запускается
sensitivity-вариант без `target_mg_sulfur > 100`. Классификатор `S > 10` использует все
валидные лабораторные результаты в обоих вариантах.

Для ПАК применяется двухконтурная схема:

1. `full` — ПАК + 24-2000 + АВТ;
2. `telemetry_only` — 24-2000 + АВТ, fallback при невалидном ПАК.

Зависший ПАК не удаляет строку ЛИМС. После 60 минут точного flatline все числовые
признаки этого сигнала ПАК маскируются в `NaN`, а признаки состояния датчика
(`flatline_age`, флаги качества, изменение соседних значений) сохраняются. CatBoost
умеет выделять пропущенные числовые значения отдельными split'ами. Forward fill и
интерполяция длинного flatline запрещены.

## Почему выбран этот вариант

### Экстремальные значения ЛИМС

В данных есть три результата выше 100 мг/кг:

| Timestamp | S, мг/кг | Контекст |
| --- | ---: | --- |
| 2024-04-23 06:30 | 2120 | в тот же день следуют 34, 107, 6.8 и 5.0; процесс работал на необычно низкой нагрузке, ПАК был заморожен |
| 2024-04-23 10:00 | 107 | часть того же переходного эпизода |
| 2025-07-24 13:00 | 120 | рядом есть 45.9, затем 2.1; это также не одиночная точка без подтверждающего контекста |

Поэтому порог `>100` сам по себе не доказывает ошибку лаборатории. Удаление этих
строк может стереть наиболее важные нарушения качества. `MAE` ограничивает влияние
амплитуды ошибки: в отличие от `RMSE`, вклад не возводится в квадрат. Sensitivity-run
показывает, изменяют ли три спорные точки структуру модели и качество на обычных
режимах.

### Timestamp и лаг

На очищенных от длинного flatline данных лучший простой сдвиг ПАК относительно ЛИМС
составляет около 50 минут для всех проб и около 60 минут для основной группы проб в
10:00. Но результат нестабилен по годам: 70 минут в 2023–2024, 50 минут в 2025 и
0 минут в 2026. Поэтому фиксированный глобальный сдвиг не вводится.

Вместо этого baseline использует лаги 30/60/120/240/360 минут. Дополнительно
сравниваются три alignment-варианта признаков: `t`, `t-60m`, `t-120m`. Если
подтвердится, что timestamp означает время регистрации результата, а не отбора,
основной anchor будет заменён без изменения target-строк.

### Flatline ПАК

Найдено 72 exact-flatline длительностью не менее часа, 17 — не менее 6 часов и
7 — не менее суток. Для ЛИМС-проб, попавших в flatline ≥60 минут, MAE простого
ПАК-бейзлайна равен примерно 3.55 мг/кг против 1.63 вне flatline.

Самый длинный эпизод длится 46.8 дня. Внутри него ЛИМС меняется, а значительная часть
телеметрии продолжает изменяться. Значит, flatline ПАК нельзя автоматически называть
остановом установки. Это отдельное состояние качества анализатора.

Используются причинные пороги:

- `<30 минут` — `OK`;
- `30–60 минут` — `SUSPECT`, значение ещё доступно, confidence снижен;
- `≥60 минут` — `FLATLINE`, числовые признаки ПАК маскируются;
- `≥24 часов` — дополнительный severity-флаг, но не отдельное правило очистки.

Порог 60 минут выбран консервативно для baseline и должен быть подтверждён технологом.

### Резкие изменения

99.9-й процентиль ненулевого соседнего изменения ПАК равен 4.785 мг/кг за 10 минут.
Таких событий 176, но только 3 выглядят как одиночный скачок с быстрым возвратом.
Следовательно, большинство сильных изменений похоже на ступенчатый переход режима,
перезапуск или новое устойчивое состояние, а не на одиночный шум.

Скачки не удаляются массово. В признаки добавляются `delta_10m`, `abs_delta_10m`
и флаг перехода. Online-значение после сильного скачка считается неподтверждённым,
пока скачок присутствует среди двух последних соседних изменений; в этот период
снижается confidence. Порог скачка вычисляется только на train-периоде: для текущей
выборки он равен 4.891 мг/кг за отсчёт. Число 4.785 — диагностический q99.9 по всей
истории, а не production-константа.

## Отделение остановов от плохих данных

`PAK_FLATLINE` и `PROCESS_OFF` — разные состояния.

`PROCESS_OFF` можно выставлять только по нескольким независимым признакам нагрузки
(подача сырья, выпуск продукта, давления/температуры, подтверждённый status tag) либо
по журналу остановов. Одинаковые значения 240/251/252/307 нельзя удалять глобально:
на отдельных тегах они могут быть физически допустимыми. Подозрителен одновременный
переход множества разнотипных тегов в один код; например, 26.04.2024 значение 240
одновременно имели 37 из 71 каналов АВТ.

До получения журнала событий вводятся режимы:

- `NORMAL`;
- `TRANSITION`;
- `LOW_LOAD_CANDIDATE`;
- `SUSPECT_DATA`;
- `UNKNOWN`.

Из primary-training исключаются только подтверждённые `PROCESS_OFF` и физически
невалидные строки. Неподтверждённые переходы сохраняются с regime/data-quality flags.

## Матрица первого эксперимента

| Run | Target | Признаки | Anchor | Назначение |
| --- | --- | --- | --- | --- |
| A | все значения, MAE | full, ПАК маскируется при flatline | t | основной baseline |
| B | без S > 100, MAE | как A | t | sensitivity к target-extremes |
| C | все значения, MAE | telemetry-only | t | fallback и ablation ПАК |
| D | все значения, MAE | full | t-60m | sensitivity timestamp/лага |
| E | все значения, MAE | full | t-120m | консервативная проверка timestamp |

Для каждого run сохраняются одинаковые календарные train/validation/test периоды.
Внутри train используются expanding blocked folds с временным gap не меньше 6 часов.
Поскольку ЛИМС-пробы нерегулярны, folds задаются календарными границами, а не равным
числом строк.

## Критерий выбора champion

Модель не выбирается по одной общей MAE. Сравниваются:

- MAE и MedianAE на всех данных и отдельно при `S ≤ 100`;
- recall/precision/PR-AUC для `S > 10`;
- Brier score и calibration curve вероятности нарушения;
- качество по годам и режимам;
- качество при `PAK_OK`, `PAK_SUSPECT`, `PAK_FLATLINE`, сильном переходе и low-load;
- доля отказов/fallback и ширина prediction interval.

Run A становится champion только если он устойчивее B по временным folds и заметно
лучше C в нормальном состоянии ПАК. При плохом ПАК production-router использует C.

## Не выбранные варианты

- Удалить все `S > 100`: теряются потенциально реальные аварийные/переходные режимы.
- Винзоризировать target: меняется лабораторная истина и занижается тяжесть нарушения.
- Сделать RMSE основной функцией: 2120 начинает доминировать по амплитуде.
- Интерполировать/forward-fill ПАК: синтетическое значение маскирует отказ анализатора.
- Удалить все сильные скачки: почти все они не являются одиночными выбросами.
- Считать каждый flatline остановом установки: это опровергается изменяющейся
  телеметрией внутри длинных зависаний.

## Воспроизводимость

Числа получены скриптом `scripts/analyze_signal_anomalies.py`. Полный машинно-читаемый
результат: `data/processed/signal_anomaly_report.json`, краткий отчёт:
`data/processed/signal_anomaly_report.md`.

После фиксации этой стратегии варианты A–E были обучены 2026-09-18. Затем как
exploratory были добавлены F, предсказывающий поправку `LIMS − PAK`, и G с
выбором масштаба этой поправки по blocked OOF. OOF выбрал полный масштаб `1.00`.
H повторяет residual-постановку G и выбирает `raw/sigmoid` на последнем
хронологическом OOF-блоке. OOF выбрал sigmoid (Brier 0,1224 против 0,1338 у raw),
но на test калибровка ухудшилась; H допускается только в shadow-режим.
Ни один вариант
не прошёл MAE-gate относительно текущего значения ПАК: F/G/H получили 1,3629
против 1,3128 у ПАК. Champion не назначен. Результаты находятся в
`artifacts/experiments/COMPARISON.md`.
