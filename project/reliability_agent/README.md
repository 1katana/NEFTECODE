# Автономный ReliabilityAgent

Рабочая версия на исходных `data/avt_tags.csv` и `data/242000_tags.csv`. Не требует готовности QualityAgent, общей витрины, Notion, LLM или подключения к облаку. Модели уже обучены: `artifacts/model.joblib`.

## Назначение

Получить снимок технологического состояния и вернуть **индекс режимного риска**, доверие к данным, наблюдаемые факторы и при необходимости сравнение с предложенным изменением. Индекс объединяет ML-оценку необычности сочетания сигналов, отклонение от исторической области и явно настроенные ограничения.

Это не вероятность аварии, прогноз остаточного ресурса или диагноз оборудования. История не размечена отказами; часто встречавшийся режим не доказанно безопасен. Пустая конфигурация технологических пределов означает, что физическая допустимость не установлена. Эти ограничения отражены и в JSON-ответах.

PDF команды использованы как предложения по интеграции. Формат первого уровня сохраняет знакомые поля, но добавляет честное состояние `UNKNOWN` и `risk_score: null`, когда оценка невозможна. Точный интерфейс этой реализации описан ниже и в `schema.json`.

## Запуск из корня проекта, PowerShell

Оценка реального момента из исходных CSV:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent assess --at "2026-02-01 12:00" --output reliability_agent/result.json
```

Оценка JSON без доступа к CSV:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent assess --state reliability_agent/examples/state.json
```

Сравнение с кандидатом:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent compare --state reliability_agent/examples/state.json --candidate reliability_agent/examples/candidate.json
```

Пример кандидата — гипотетическое изменение сигнала T55, **не подтверждённое управление печью**. По умолчанию whitelist управляющих параметров пуст; такой кандидат получает `candidate_controls_supported: false`, предупреждение и LOW confidence. Его численная оценка позволяет исследовать чувствительность режима, но не подтверждает возможность управления этим тегом.

HTTP-сервис:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent serve --host 127.0.0.1 --port 8765
```

- `GET /health` — модель загружена.
- `GET /schema` — документированная схема запроса и ответа.
- `POST /assess` — `{"state": ProcessState, "candidate": CandidateAction|null}`.
- `POST /compare` — `{"state": ProcessState, "candidate": CandidateAction}`.
- Ошибки структуры возвращаются HTTP 400; корректное состояние с недостаточными данными — HTTP 200 с UNKNOWN.

Пример вызова:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8765/compare -Method Post -ContentType 'application/json; charset=utf-8' -InFile reliability_agent/examples/request.json
```

Прямой вызов в Python:

```python
from reliability_agent import ReliabilityAgent

agent = ReliabilityAgent()
current = agent.assess(state)
comparison = agent.compare(state, candidate)
```

## ProcessState

Обязательны `timestamp` и `telemetry`. Телеметрия — словарь вида `avt_t55: число`, `hyd_f26: число`. Нельзя передавать просто `F26`: такой тег есть на двух установках. Допускаются регистр букв, `avt:T55` и префикс `242000_` как алиас `hyd_`; конфликтующие алиасы отклоняются. Отсутствие значения — `null`, не NaN/Infinity/0.

Полный рабочий пример находится в `examples/state.json`. Формат метаданных одного сигнала:

```json
{
  "flag_missing": false,
  "flag_stale": false,
  "flag_outlier": false,
  "age_min": 0,
  "flatline_min": 0
}
```

Эти объекты лежат в `data_quality` под именами тегов. Также принимаются плоские поля `avt_t55_flag_missing`, `avt_t55_flag_stale`, `avt_t55_flag_outlier` внутри `data_quality`. Внутрь `telemetry` флаги не подмешиваются.

`source_timestamp` опционально задаёт время исходного среза. Его возраст относительно `timestamp` учитывается для всех сигналов; будущий источник отклоняется. Время CSV не содержит timezone: CLI по датам использует ту же локальную шкалу. HTTP принимает согласованные временные зоны. Агент не сравнивает историческую дату с системными часами.

`scope` — необязательный список узлов: `avt_p3`, `avt_k10`, `avt_k2`, `hyd_regime`. По умолчанию нужны все четыре. Явная оценка одного узла возможна без сигналов остальных; неполное покрытие никогда не скрывается при полном scope.

При использовании исходных CSV загрузчик самостоятельно рассчитывает длительность точного плато **только по прошлым значениям**. Порог подозрения — 12 часов; разрыв сетки начинает отсчёт заново. Это настраиваемая эвристика достоверности, не метка неисправности. HTTP по одиночному снимку не может восстановить плато: upstream должен передавать флаги/длительность. Отсутствие метаданных понижает confidence.

`quality` и другие общие поля ProcessState могут присутствовать, но не требуются агенту. Текущие CONTROL берутся из телеметрии; отдельное поле current_controls не применяется как второй противоречащий источник значений.

## CandidateAction

```json
{
  "candidate_id": "scenario-1",
  "mode": "delta",
  "changes": {"avt_t55": 20}
}
```

`mode: absolute` (по умолчанию) означает новые значения; `delta` — приращения. Кандидат применяется к копии состояния. Исходный state не меняется; гипотезы не дописываются в историю. Неизвестный сигнал, отсутствие исходного значения и неоднозначный формат отклоняются.

Численная оценка — **статический прокси для изменённых параметров на фоне текущего контекста**. Она не предсказывает будущую реакцию остальных потоков или датчиков. Нельзя принимать её за причинный прогноз последствий управления.

Чтобы считать CONTROL поддержанным, передайте собственный подтверждённый `--policy path.json` с `controls`. Для каждого параметра нужны источник, единица, границы, при необходимости max_delta. В поставленном `policy.json` controls и technology_bounds намеренно пусты: предоставленные материалы не задают подтверждённых значений. Чужие или придуманные нормативы не внесены.

Конфигурация ограничений имеет вид `"имя_тега": {"min": число, "max": число, "unit": "...", "source": "..."}`. Допускается только одна сторона границы. Для controls возможен `max_delta`. Внести конфигурацию можно независимо от других сервисов; схема загрузки уже работает и проверена тестами с явно тестовыми пределами.

## Ответ

Обязательные поля: `reliability_risk`, `risk_score`, `data_confidence`, `warnings`.

- Индекс 0–1: больше означает более выраженный риск по используемым прокси.
- LOW: <0.35; MEDIUM: 0.35–<0.7; HIGH: ≥0.7. Это проектные пороги, не технологические нормативы.
- UNKNOWN/null: не хватает критических сигналов, применимости к режиму или данных для настроенного предела. Не заменять null нулём при интеграции.
- `partial_risk_score` показывает оценку доступной части и не заменяет отсутствующий общий вывод.
- `assets` — отдельные узлы, покрытие признаков, компоненты оценки и объяснения.
- `risk_factors` — конкретные значения, направление отклонения, исторические ориентиры или источник настроенного ограничения.
- `candidate_controls_supported` — отдельная проверка поддержки изменений; false должен учитываться принимающим решением компонентом.
- `technology_limits_configured` и warnings показывают отсутствие физических нормативов.

Общий балл — максимум доступных компонент, без усреднения серьёзного превышения с благополучными узлами. Если один обязательный узел неизвестен, общий ответ UNKNOWN; подтверждённое нарушение настроенного предела всё равно возвращается HIGH с LOW confidence при неполном покрытии.

`compare` возвращает current/candidate ответы, `current_risk`, `candidate_risk`, `risk_delta = candidate - current` и изменившиеся факторы. При неизвестной общей оценке delta тоже null.

Ни один ответ агента не является `constraint_passed`, RECOMMEND или командой оборудованию. Эти решения остаются у вызывающей системы.

## Обучение и измеренные результаты

У каждого из четырёх узлов собственный Isolation Forest: 128 деревьев, до 30 000 исторических строк для fit, фиксированный seed. Это обучение без меток отказов; модель изучает совместные режимы. ЛИМС/ПАК и результаты QualityAgent не участвуют.

История: 189 217 моментов, 01.01.2023–07.08.2026. Train — до 01.01.2026; калибровка — январь–апрель 2026; test — с 01.05.2026. В тесте ничего не дообучалось.

Для обучающей опоры используются полные пригодные наблюдения с подачей. Состояния ниже 25% медианной train-подачи вынесены за область применимости; это модельная эвристика, не физический минимум. Широкий фильтр median ±20 IQR применяется только к обучающей опоре, не удаляет строки из исходников и не объявляет их отказами. Необычные состояния остаются доступны для оценки.

В inference отсутствующий некритический контекст допускается заполнять обучающей медианой только при покрытии не менее 80%, с явным предупреждением и MEDIUM confidence. Критические сигналы так не восстанавливаются. Флаг outlier снижает доверие, но сам по себе не стирает реально высокое значение из расчёта риска.

Давление К-2 образуется из согласованной пары/тройки P22/P23/P67; допуск получен только на train. Один доступный канал или выброшенный конфликтующий канал снижает доверие. P51 не дублируется независимым голосом P50.

Гидроочистка оценивается статистически по идентификаторам сигналов. Из-за противоречий исходного справочника физическая интерпретация ограничена, что даёт отдельное предупреждение и максимум MEDIUM confidence этой группы. Процент износа катализатора не рассчитывается.

| Группа | Пригодных строк train | Доля HIGH на оценимых строках test |
|---|---:|---:|
| П-3 | 150 616 | 40.85% |
| К-10 | 152 238 | 45.30% |
| К-2 | 150 508 | 31.63% |
| 24-2000 | 150 371 | 45.00% |

Это **частоты сигналов отклонения, не точность и не частота аварий**. Высокие доли на позднем периоде — существенное ограничение текущей калибровки/области режимов. На validation HIGH составлял примерно 1.2–9.0% по группам. На 01.08.2026 обнаружены, например, большие F31/F65, выход F46 и hyd_p8 за исторические ориентиры. Без журнала режимов нельзя установить, являются ли эти изменения допустимым новым режимом, проблемой измерений или тяжёлым состоянием. Порогами под тест этот результат не скрывался.

Отчёт: `artifacts/training_report.json`. В нём есть точные количества оценимых, недоступных и низконагруженных строк, границы опоры, версии и хеш артефакта.

Демонстрация 10 разнесённых исторических моментов: 3 LOW, 2 MEDIUM, 3 HIGH, 2 UNKNOWN. Это демонстрация поведения, не независимый тест качества ML: часть моментов относится к train.

## Воспроизведение

```powershell
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent train
.\.venv\Scripts\python.exe -X utf8 -m reliability_agent.demo
.\.venv\Scripts\python.exe -X utf8 -m unittest reliability_agent.test_agent -v
```

Для нового окружения установите `requirements.txt` или зафиксированные версии из `requirements-lock.txt`. Запускать из корня проекта. Для inference достаточно Python-пакета, локального доверенного `model.joblib` и входного JSON; исходные CSV нужны только для обучения и CLI-выбора исторической строки.

Тесты проверяют HTTP/JSON, повторяемость после загрузки, пропуски, плато, устаревание, конфликт датчиков, неизменность текущего состояния при candidate, неподтверждённые управления и приоритет заданных ограничений.
