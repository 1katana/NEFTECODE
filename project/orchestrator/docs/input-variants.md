# Варианты входа оркестратора

Этот документ фиксирует поведение версии контракта `1.0.0`. Входом является
`OrchestratorInput`, а бизнес-ответы внешних блоков оборачиваются в
`ComponentResult`.

## Состояния вызова компонента

| status | data | error_code | Решение |
| --- | --- | --- | --- |
| `OK` | обязательно | отсутствует | обработать бизнес-результат |
| `TIMEOUT` | отсутствует | обязательно | `REFUSE` |
| `ERROR` | отсутствует | обязательно | `REFUSE` |
| `INVALID_RESPONSE` | отсутствует | обязательно | `REFUSE` |
| `UNAVAILABLE` | отсутствует | обязательно | `REFUSE` |

## QualityAssessment

| Вариант | Допустимость | Поведение |
| --- | --- | --- |
| Полный прогноз, probability и interval | допустимо | обычная обработка |
| Interval отсутствует | допустимо | решение возможно |
| Основной прогноз отсутствует | контракт допустим как деградация | `REFUSE` |
| Probability отсутствует | контракт допустим как деградация | `REFUSE` |
| Probability вне `[0, 1]` | невалидно | `REFUSE_CONTRACT_INVALID` |
| Confidence `HIGH` | допустимо | `RECOMMEND`, `KEEP` или `REFUSE` |
| Confidence `MEDIUM` | допустимо | максимум `KEEP` |
| Confidence `LOW/UNKNOWN` | допустимо | `REFUSE` |

## ReliabilityAssessment

`LOW`, `MEDIUM` и `HIGH` являются валидными оценками риска. Оркестратор не
превращает `HIGH` в технологический запрет самостоятельно: разрешение конкретного
сценария принадлежит Safety. `risk_score` и числовая confidence находятся в
диапазоне `[0, 1]`.

## SafetyResult

| constraint_passed | violations | Допустимость |
| --- | --- | --- |
| `true` | пусто | валидно |
| `false` | непусто | валидно |
| `false` | пусто, но есть `rejection_reason` | валидно |
| `true` | непусто | невалидно |
| `false` | пусто и нет причины | невалидно |

## OptimizationResult

| status | ranked_candidates | Поведение |
| --- | --- | --- |
| `SUCCESS` | один или больше | использовать rank 1 |
| `NO_FEASIBLE_SOLUTION` | пусто | `KEEP`, если текущий режим безопасен; иначе `REFUSE` |
| `SUCCESS` | пусто | невалидно |
| `NO_FEASIBLE_SOLUTION` | непусто | невалидно |

Каждый ranked candidate обязан существовать в `scenarios`, иметь тот же payload и
`constraint_passed=true`. Rank начинается с 1, не содержит дублей и пропусков.

## Итоговые логические ветки

| Текущий режим | Результат оптимизации | Confidence | Решение |
| --- | --- | --- | --- |
| безопасен | безопасное изменение rank 1 | высокая | `RECOMMEND` |
| небезопасен | безопасное изменение rank 1 | высокая | `RECOMMEND` |
| безопасен | `NO_CHANGE` rank 1 | средняя или высокая | `KEEP` |
| безопасен | `NO_FEASIBLE_SOLUTION` | средняя или высокая | `KEEP` |
| небезопасен | `NO_FEASIBLE_SOLUTION` | любая | `REFUSE` |
| безопасен | изменение rank 1 | средняя | `KEEP` |
| любой | любой | низкая или неизвестная | `REFUSE` |
| любой | ошибка обязательного компонента | любая | `REFUSE` |
| любой | нарушение контракта или ссылочной целостности | любая | `REFUSE` |

Эталонные JSON для каждой ветки находятся в `examples/`.
