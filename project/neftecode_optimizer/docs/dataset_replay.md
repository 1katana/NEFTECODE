# Офлайн-проверка оптимизатора на датасете v2

`датасеты.zip` нужен нашему блоку для проверки интеграции и поведения на
реальных исторических состояниях. Оптимизатор при обычном запуске не читает
этот ZIP: ему передают `ProcessState` и оценки агентов.

В архиве есть `quality_training_hydro2_v2.csv` (1888 лабораторных событий),
`split_train_v2.csv`, `split_val_v2.csv`, `split_test_v2.csv` и
`view_quality_v2.csv` (10-минутная оперативная витрина). Проверочный split
содержит 126 строк, 27 текущих режимных тегов на строку; `target_mg_sulfur`
заполнен в 112 строках. Его цель — сера в точке
«Гидроочистка / точка 2 / Дизельное топливо», **не подтверждённый показатель
товарного дизеля после блендинга**.

README внутри архива упоминает `process_state_v2.csv`, но этого файла в ZIP
нет. Поэтому адаптер `optimization.historical_data.iter_historical_cases`
потоково читает готовые split-файлы без распаковки:

```python
from optimization import iter_historical_cases

for case in iter_historical_cases("датасеты.zip", split="test", limit=5):
    result = optimizer.search(case.state)
    print(case.row_number, result.status, result.uses_mock_assessments)
```

`case.state.values` содержит только столбцы `tele_*_current`. Имена
сохранены буквально: из них нельзя угадывать физический смысл или право
управления. `case.state.source=HISTORICAL`; действия по умолчанию запрещены.
`timestamp` — время забора пробы ЛИМС; консервативная runtime-доступность
фиксируется в `metadata.lims_available_at = timestamp + 4h`. В `metadata`
также сохраняются время и возраст телеметрии, её доступность и
флаг диапазона источника. Адаптер отклоняет телеметрию из будущего;
Safety отклоняет состояние, если `telemetry_available` явно не равно `True`.
Числовой порог старения не придуман и должен быть согласован отдельно.

`case.observed_hydro2_sulfur_mg_kg` и флаги невалидного/аномального
лабораторного значения лежат **вне** `ProcessState`. Текущий LIMS target,
предыдущие LIMS-значения и лаговые/rolling-признаки из таблицы не передаются
агенту автоматически. До наступления `lims_available_at` лабораторный результат
не может быть входом агента; target доступен отдельно только для ретроспективной
оценки.

Такой прогон проверяет: загрузку состояний, устойчивость к пропускам, работу
KEEP/отказа, прохождение контрактов агентов и объяснимость Safety. Он **не**
оценивает качество контрфактического прогноза: в пассивной истории нет
наблюдаемого результата каждого альтернативного действия. Для реального
QualityAgent Гера сама должна подготовить согласованные признаки, лаги и
границы применимости; нельзя выдавать LIMS после гидроочистки за прогноз
товарного продукта. Подтверждённые имена `T6/F9/P13` не превращают исторические
числа в утверждённые промышленные min/max.

Проверочный прогон подтверждает только сквозную совместимость формата. Он не
доказывает качество рекомендаций или причинный эффект CONTROL.
